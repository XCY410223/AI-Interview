# 忘记密码找回 — 设计方案

> 模块：账户（M1 补全）
> 分支：`feature/password-reset`（从 `dev` 切出）
> 状态：**待人工评审**（CLAUDE.md 工作流：先规划后写码）
> 依赖现状：复用 M1 已有设施 —— bcrypt(cost=12)、JWT 双 token、Redis 滑动窗口限流（`app/core/rate_limit.py`）、Celery、全局异常协议 `{code, message, data}`

---

## 1. 方案选型

| 维度 | A. 邮件链接（一次性 token）✅ 推荐 | B. 邮箱验证码（6 位数字） |
|---|---|---|
| 用户操作 | 点链接直达重置页，一步完成 | 切换 App 抄码，两步操作 |
| 状态管理 | Redis 存 `sha256(token)→user_id`，TTL 即过期 | 需额外维护验证码 + 尝试次数计数器 |
| 安全性 | 43 字符高熵 token，单次失效，URL 泄露窗口 = TTL | 6 位仅 10^6 空间，必须配套失败锁定逻辑 |
| 邮件内容 | 无状态链接，模板简单 | 需提示"10 分钟内有效"，且要防爆破 |
| 扩展性 | 后续可加短信/OAuth 找回，均落到同一 reset 端点 | 各通道各自维护验证码状态 |

**结论：方案 A。** 注册即强邮箱唯一键（`users.email unique`），邮件链接是最自然的找回通道；验证码方案作为二期扩展（预留 `channel` 字段位），不在本期实现。

**不做 DB 新表、不生成 Alembic 迁移**：重置 token 全部放 Redis（TTL 15 分钟天然过期，无需清理任务），规避迁移终审流程。审计需求见 §7 可选项。

## 2. 整体流程

```
用户                前端                      后端                         Redis/Celery
 │  输入邮箱        │                          │                              │
 ├────────────────►│ POST /auth/forgot-password│                              │
 │                 ├─────────────────────────►│ IP 限流 + 邮箱限流检查         │
 │                 │                          ├─ 邮箱是否存在（不外泄）────────►
 │                 │                          │  存在 → 生成 token            │
 │                 │                          │  sha256(token) SETEX 15min   │
 │                 │                          ├─ 投递 Celery 邮件任务─────────►
 │  统一提示       │◄──────── 200 {message} ──┤                              │
 │  "如邮箱已注册， │                          │                        worker 发信
 │   已发送邮件"   │                          │                              │
 │                 │                          │                              │
 │  点邮件链接     │ GET /reset-password?token=xxx                              │
 ├────────────────►│ 页面加载时(可选)校验 token  │                              │
 │                 ├─────────────────────────►│ GET /auth/reset-password/validate
 │  输入新密码     │ POST /auth/reset-password │                              │
 │                 ├─────────────────────────►│ GETDEL sha256(token) 原子取删  │
 │                 │                          │  改密 bcrypt(cost=12)         │
 │                 │                          │  撤销该用户全部 refresh token  │
 │  跳转登录       │◄──────── 200 ────────────┤                              │
```

**核心安全语义（逐条对应规范 §11）：**

1. **防账号枚举**：`forgot-password` 无论邮箱是否注册，一律返回 200 + 相同文案；耗时侧信道用「不存在的邮箱也跑一次 dummy bcrypt」抹平。
2. **单次有效**：Redis `GETDEL` 原子「取出即删除」，同一 token 第二次使用直接失败（天然防重放）。
3. **重置即全下线**：新密码生效时，将该 `user_id` 名下**所有** refresh token 置 `revoked`（防止密码泄露期间已登录的攻击者会话继续存活）。
4. **限流复用现有滑动窗口**：
   - IP 级：`window_record(key=forgot:ip:{ip}, window=3600s)`，上限 10 次/小时
   - 邮箱级：`window_record(key=forgot:email:{sha256(email)}, window=3600s)`，上限 3 次/小时（防邮件轰炸）
   - 命中限流抛 `RateLimitExceeded` → 全局异常处理器转 429
5. **token 不落库、不进日志**：Redis 只存 `sha256(token)`；邮件任务日志只记 `user_id`，禁止打印 token/邮箱正文。

### 3.2 API（`app/api/v1/auth.py` 追加，先 grep 确认无重复路由）

| 方法 | 路径 | 请求 | 成功响应 | 错误码 |
|---|---|---|---|---|
| POST | `/auth/forgot-password` | `{email}` | `200 {code:0, message:"如邮箱已注册，重置邮件已发送", data:null}` | 429 限流；422 参数非法 |
| GET | `/auth/reset-password/validate` | `?token=` | `200 {valid:true}` | `200 {valid:false}`（不区分过期/无效，防探测） |
| POST | `/auth/reset-password` | `{token, new_password}` | `200 {code:0, message:"密码已重置，请重新登录", data:null}` | 400 token 无效/过期（统一文案）；422 密码强度不足 |

### 3.4 安全工具（`app/core/security.py` 追加）

```python
def generate_reset_token() -> str:
    """secrets.token_urlsafe(32) → 43 字符高熵 token，仅存在于邮件链接中。"""

def hash_reset_token(token: str) -> str:
    """sha256(token + SECRET_KEY)——与 refresh token 存根同款策略，Redis 不存原文。"""
```

### 3.5 业务服务（新增 `app/services/auth/password_reset_service.py`）

```python
class PasswordResetService:
    RESET_KEY = "pwd_reset:{token_hash}"        # value=user_id, TTL=15min

    @staticmethod
    async def request_reset(db, redis, email: str, ip: str) -> None:
        """限流检查 → 查用户 → 存 token → 投递 Celery 任务。不存在用户静默返回。"""

    @staticmethod
    async def validate(redis, token: str) -> bool: ...

    @staticmethod
    async def reset_password(db, redis, token: str, new_password: str) -> None:
        """redis.get(key) 后立即 delete（GETDEL 语义）→ 无则抛 AuthResetTokenInvalid
        → bcrypt 改密 → 批量撤销该 user_id 全部 refresh token → 单事务 commit。"""
```

**TokenService 需补一个方法**（现有只支持按 jti 链撤销，不满足"全下线"语义）：

```python
@staticmethod
async def revoke_all_for_user(db: AsyncSession, user_id: int) -> int:
    """UPDATE refresh_tokens SET revoked=true WHERE user_id=:uid AND revoked=false。"""
```

### 3.6 Celery 邮件任务（新增 `app/tasks/email.py`）

- 红线 4 精神：SMTP 是慢 I/O，**禁止在 HTTP 请求内同步发信**，统一走 Celery。
- 模板集中管理（类比红线 9「Prompt 集中管理」）：`app/services/auth/email_templates.py` 常量模板，含重置链接 `${FRONTEND_BASE_URL}/reset-password?token=...`、有效期提示、"非本人操作可忽略"说明。
- 重试策略：`bind=True, max_retries=3, retry_backoff=True`；任务参数只传 `user_id` 和 `token`，**不传邮箱明文**（worker 内自查用户），日志脱敏。
